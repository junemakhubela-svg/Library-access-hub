# WCAG 2.1 AA Mapping Matrix — Pretoria Library Access Hub

> **Ticket:** MD-2026-0143 · **Conformance target:** WCAG 2.1 Level AA
> **Scope:** Wireframe suite (`/wireframes`) and React prototype (`/src`)
> **Verification tooling:** axe-core 4.x (automated, via Vitest + jsdom), Chrome Lighthouse, NVDA + Firefox, VoiceOver + Safari, manual keyboard pass

| # | Criteria ID & Name | Target Interface Component | Technical Implementation Detail | Verification Strategy |
|---|---|---|---|---|
| 1 | **1.3.1 Info and Relationships** (A) | Page shell (`Layout.jsx`), booking form fieldsets, results list | Landmarks via `<header>`, `<nav aria-label="Main">`, `<main id="main-content">`, `<aside aria-labelledby>`, `<footer>`. One `<h1>` per view; `<h2>`/`<h3>` nest without skipping levels. Radio groups wrapped in `<fieldset>` + `<legend>`. Resource metadata in `<dl>`. Results rendered as `<ul>` of `<article>`. | axe rules `landmark-*`, `heading-order`, `list`, `definition-list`. NVDA Elements List (`Insert+F7`) → Landmarks and Headings tabs show the expected outline. |
| 2 | **1.3.5 Identify Input Purpose** (AA) | `LiveForm.jsx` — name and email fields | `autoComplete="name"` and `autoComplete="email"` on the corresponding inputs so browsers and AT can auto-fill and personalise. | axe `autocomplete-valid`. Manual: browser autofill offers saved name/email. |
| 3 | **1.4.3 Contrast (Minimum)** (AA) | All text: body copy, muted hints, buttons, header, error and success messages | Palette tokens in `:root`. Body `#1A202C` on `#FFFFFF` = **16.32:1**; hints `#4A5568` on `#FFFFFF` = **7.53:1**; button text `#FFFFFF` on `#2B6CB0` = **5.42:1**; errors `#C53030` on `#FFFFFF` = **5.47:1**; success `#22543D` on `#F0FFF4` = **8.45:1**. Ratios documented in CSS comments. | Lighthouse / axe `color-contrast` in a real browser (jsdom cannot compute colour). Spot-check with WebAIM Contrast Checker. |
| 4 | **1.4.11 Non-text Contrast** (AA) | Input borders, focus rings, toggle buttons, checkboxes | Input borders `#718096` on `#FFFFFF` = **4.02:1** (≥ 3:1). Focus ring `#2B6CB0` on white = **5.42:1**; on the dark header the ring switches to `#FBD38D` on `#1A365D` = **8.56:1**. Pressed toggles change fill *and* show a ✓ glyph so state is not colour-only. | Manual inspection with Windows High Contrast / `forced-colors` emulation in DevTools; WebAIM checker for border colours. |
| 5 | **2.1.1 Keyboard** (A) | All interactive controls: nav, toggles, accordion, cards, modal, form | Only native interactive elements (`<a href>`, `<button>`, `<input>`, `<select>`, `<textarea>`) are used, so `Enter`/`Space` activation is built in. No `div` click handlers. No positive `tabindex`. | Unplug mouse; complete "find → filter → open details → book → confirm" with keyboard only. axe `tabindex`, `nested-interactive`. |
| 6 | **2.1.2 No Keyboard Trap** (A) | `Modal.jsx` | Focus is intentionally cycled inside the dialog while it is open (modal pattern), but `Esc` and the visible **Close** button always release it. App root gets `inert` while open and loses it on close. | Open dialog → `Tab` 10× and `Shift+Tab` 10× (focus stays inside) → `Esc` → focus returns to the "View details" button that opened it. Automated test asserts focus restoration. |
| 7 | **2.4.1 Bypass Blocks** (A) | `Navigation.jsx` → `SkipLink` | First focusable element is "Skip to main content", visually hidden until focused. Click handler calls `preventDefault()` (so hash routing is unaffected) and `mainRef.current.focus()` on `<main tabIndex={-1}>`. | Load page → `Tab` once → link is visible → `Enter` → next `Tab` lands on first control inside `<main>`. |
| 8 | **2.4.2 Page Titled** (A) | `App.jsx` route effect | `document.title` updates on each view switch, e.g. "Find resources \| Pretoria Public Library". | NVDA `Insert+T` reads the new title after navigation. |
| 9 | **2.4.3 Focus Order** (A) | SPA view switches, modal, error summary | DOM order equals visual order (CSS grid never reorders). On view change, `useRef` moves focus to the new `<h1 tabIndex={-1}>`. On failed submit, focus moves to the error summary. On success, focus moves to the confirmation heading. | Keyboard pass with tab-sequence log (README §4). Automated test asserts `document.activeElement` after submit. |
| 10 | **2.4.7 Focus Visible** (AA) | Global (`index.css`, `main.css`) | `:focus-visible { outline: 3px solid #2B6CB0; outline-offset: 2px; }`. Dark header overrides to `#FBD38D`. Outlines never removed without replacement; `forced-colors` keeps a system-colour outline. | Keyboard pass at 100% and 400% zoom; every stop shows a 3 px ring. |
| 11 | **3.3.1 Error Identification** (A) | `LiveForm.jsx` | Each invalid field gets `aria-invalid="true"` and an error `<p id="{field}-error">` prefixed with visually-hidden "Error:", added to the field's `aria-describedby`. Error summary lists every error as an in-page link. | Submit empty form → axe finds no violations in error state; NVDA reads "invalid entry" plus the error text on each field. |
| 12 | **3.3.2 Labels or Instructions** (A) | `LiveForm.jsx`, search input | Persistent `<label htmlFor>` for every control; format hints (e.g. "8 digits, on the back of your card") linked via `aria-describedby`; optional fields marked "(optional)". | axe `label`, `aria-valid-attr-value`. NVDA reads label → role → hint for each field. |
| 13 | **3.3.3 Error Suggestion** (AA) | `LiveForm.jsx` validators | Messages state how to fix: "Your library card number must be exactly 8 digits", "Choose today's date or a date in the future". | Content review against GOV.UK error message guidance; screen-reader pass. |
| 14 | **4.1.2 Name, Role, Value** (A) | Category toggles, "More filters" accordion, modal | Toggles: `<button aria-pressed={bool}>` bound to React state. Accordion: `<button aria-expanded={open} aria-controls="more-filters-panel">` with `hidden={!open}` on the panel. Dialog: `role="dialog" aria-modal="true" aria-labelledby`. | Automated tests assert `aria-pressed`/`aria-expanded` flip on click. NVDA announces "toggle button, pressed" / "collapsed → expanded". |
| 15 | **4.1.3 Status Messages** (AA) | Results count, blur validation, booking confirmation | `role="status" aria-live="polite"` regions announce "4 of 12 resources shown" (debounced 600 ms; `aria-busy` on the results list while pending), field errors on blur, and the confirmation reference — without moving focus. | NVDA speech viewer log confirms one announcement per change; automated test asserts live region text. |
